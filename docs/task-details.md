# Task details, checklists and task organisation - Stages 1 to 4

Tasks now consolidates secondary row actions into the three-dot **Task actions** button. The same menu opens by right-clicking non-editable task space or using Shift+F10/the Context Menu key from a focused row. The shared site menu handles text editors and links; Shift-right-click retains the native browser menu everywhere. Controls without text selection APIs retain their native menu. Completion and dragging remain direct controls; Enter/F2 still opens details and Alt+Up/Down still reorders.

The menu provides details, Rename (the existing explicit-save title editor), Schedule navigation, completion status, move up/down, move to section, copy title and Archive. Labels and availability are rechecked against exact task IDs, current identity and canonical state at invocation. Recurring-series completion, pending saves, sorted movement and first/last boundaries retain their existing restrictions. Existing commands, receipt-safe Retry, confirmed Undo and instant completion/reorder previews are reused.

Use Up/Down, Home/End and Enter/Space inside the menu. Escape dismisses it and restores the invoker; Tab leaves it. Outside pointer-down, task-workspace scrolling, viewport resize, section navigation and account/planner changes dismiss it. Failed clipboard access reports an error. Multi-selection, Duplicate and bulk actions remain later stages.

In Tasks, use **Task details** on a task row, or focus the row and press Enter/F2. Wide desktop windows show a side pane; smaller desktop windows use the expanded dialog. Expand opens the same draft in a larger dialog.

The editor saves title, notes, scheduled date/start/duration, deadline, priority, reminder lead, repeat rule, colour, preferred time and AI schedule lock. Ordinary start-time moves preserve duration; an explicit duration edit resizes the task. Existing fields not exposed here are retained. Repeat changes apply to the entire series; individual occurrence actions remain in Schedule. Move/completion/archive/permanent-delete actions continue through their existing controls or **More actions in Schedule**.

Save is explicit. Closing or selecting another task with a draft offers Save, Discard draft or Stay. A network failure retains the draft and pins Retry to its original operation identity; session storage retains pending saves for reconciliation after reload. Discarding an uncertain draft does not undo a save that may already have succeeded: inspect the task afterward. Validation failures remain editable. Account or planner changes invalidate the editor.

Commands use the existing Firestore transaction store and bounded action receipt fields; no new collection or bulk migration is introduced. Only deliberately changed fields are persisted. Schedule-dependent edits check the baseline start/duration as well. Same-field edits, moved/archived/deleted targets and invalid recurrence dates fail with a notice. New accounts initialise their normal planner before capturing an edit identity.

The host waits for queued saves, captures the current local state, applies the transactional command and rebases subsequent local changes against the server result. This avoids treating Schedule metadata normalisation as an unrelated edit conflict. User text and attributes are escaped; task modules load once when Tasks is prepared.

Checklists support adding, renaming, checking, removing and moving steps up/down in the same explicit-save draft. Each step has a stable ID, title and completion flag. The product limits are 100 steps per task and 180 characters per step title. Completing steps does not complete the parent task, create scheduled tasks, trigger reminders or consume task quota. Task rows show progress counts.

Checklist edits keep existing rows and caret positions stable. Enter in the entry field adds a step; Enter / Shift+Enter in a step title moves to the next / previous title. Paste multiple lines into the entry field to add several steps, using either native paste or the site menu. Selected entry text is replaced before lines are split. Invalid or over-limit additions leave the draft and entry text intact.

Drag a checklist step using its grip, or press Alt+Up/Down from its title or grip. Arrow buttons remain available. Dragging starts after 4px and shows a text preview and insertion line; long panes scroll near the edges. Only a valid drop changes the draft order. Escape cancels the gesture before closing details; outside release, pointer cancellation, lost capture, focus loss, page/account/planner changes and disabling the draft cancel it too. Reordering does not save until explicit Save; Retry preserves the exact step order and IDs.

Save and Ctrl/Cmd+Enter include unfinished entry text. That text also triggers Save/Discard/Stay when closing. IME composition does not trigger an addition or Save. Confirmed saves restore logical checklist focus, caret and scroll; expanding uses the same editor and draft. Delayed saves never restore old focus after account, planner or page changes, or after focus moves elsewhere. Retry retains its original payload and step IDs.

Recurring tasks expose an unchecked **Series template**. Choose a logical date with **Open occurrence** to track that occurrence's checklist; its other metadata remains editable in Schedule. Edited occurrences store a checklist snapshot alongside their existing exceptions, so moving an occurrence preserves its progress. Untouched occurrences inherit the current template unchecked; template edits retain historical snapshots. Converting a checked ordinary checklist into a recurring series displays an unchecked template, including conversions made in Schedule.

Independent changes to different step IDs merge. Conflicting changes to the same field or competing existing-step orders fail with a notice and preserve the draft. New steps retain their chosen insertion position when saved. Lost-response retries use the same operation and step identities. Durable receipts store a compact SHA-256 command fingerprint and accept existing Stage 1 receipts for retry compatibility. AI context includes checklist counts but omits step titles and historical checklist snapshots.

Use **Open section** to work through a full-width section list. **Back to boards** restores the prior board scroll and section control. Section collapse and completed visibility are local, per-account/per-planner session preferences. Selected rows remain selected when revisiting a section. An empty, archived or deleted section shows a clear state; unavailable destinations cannot create tasks.

**Add task** opens the focused section's inline quick entry. Enter submits one ordinary task and keeps the same input ready; blank input does nothing and Escape clears a draft before saving. New task titles are limited to 180 characters. Navigation retains ordinary drafts per section; these unsaved drafts do not survive reload. Pending saves survive reload and remain locked to their original destination, task ID and operation receipt; Retry reconciles that task even after the section is archived. A late result cannot clear another section's draft. Account/planner changes clear the active workspace. Focused rows update without rebuilding the quick input or an actively edited title.

If a pending creation cannot reconcile (for example, its receipt has expired), **Discard pending draft** offers explicit recovery. A confirmation explains that the task may already have saved. Discard clears only the local pending draft and does not undo a saved task; inspect the section before entering the same task again. Retry keeps its original identity throughout.

Tasks rows now expose a dedicated drag grip, Move up/down buttons and a Move to section dialog. Alt+Up/Down on a row or its controls also moves it; typing shortcuts remain untouched. Dragging shows an insertion line, scrolls near the list edges, and cancels with Escape or release outside a valid destination. Completed/archived entries retain their underlying order; visible anchors translate to the full array, so filtering does not silently reorder hidden tasks. The move dialog uses explicit section IDs even when labels match. Section groups themselves retain their existing order.

Completion, archive, move and reorder in Tasks use confirmed transactions and offer **Undo** for 10 seconds. Undo validates affected flags, location and order before reverting; newer conflicting changes or an expired window are never overwritten. Unrelated task text/checklist edits survive. Completion achievements remain counted once after confirmed completion, including if undone, consistent with existing lifetime award semantics. Home and Schedule keep their existing controls; recurring occurrence completion/date edits stay in Schedule.

Order/move actions require unchanged affected section ID orders; concurrent additions require reviewing a fresh action. Uncertain actions retain their command, inverse baseline and operation identity in session storage. Retry reconciles the original receipt; confirmed local Discard clears only the pending action, with a warning that its save may already have succeeded. Undo itself does not survive reload after a confirmed save. Sorted views cannot offer manual reordering until their order semantics are defined. Reduced motion removes row animation.

Retries recheck unsaved detail drafts before archive/move. Awaited actions remain bound to their original account/planner; explicit first-plan creation is the only permitted identity transition. Overview refresh preserves the active title/date draft and caret in the same account/planner, while later focus or scrolling is respected. Drag grips take focus so Escape remains scoped to Tasks. Overview rows wrap to retain readable titles beside their controls.

Duplicate destination labels include visible board/section positions so users can distinguish them while commands retain explicit IDs. Restored pending repeat changes show their draft rule while Retry retains the exact original command. Modal focus wrapping includes summaries and excludes closed advanced content, hidden/inert controls and disabled fieldsets.

Real pointer/keyboard feel, browser layout/focus and verified-account preview smoke remain release checks. Local browser verification attempts were blocked: debugger connections were denied by the sandbox, and headless rendering produced no usable output. The regression suite covers the restored repeat draft, distinct move choices, retries and account/planner boundaries; it does not establish authenticated Firestore behavior or visual verification.

Verification covers model validation, unknown-field preservation, concurrent changes, uncertain response/retry, first-planner creation, legacy normalisation, canonical title baselines, drafts, escaping, account changes, module load-once behaviour, checklist limits/order, compact receipts and recurring snapshots. Real-browser layout/focus and verified-account Firestore smoke checks still require a preview session.

Tasks completion and within-section reordering now preview immediately while their original durable operation saves. This preview is derived only for the Tasks overview and focused section; it never changes the canonical planner, receipts, or other pages before confirmation. New actions remain locked during the save. The saving status stays visible, and Undo and completion awards appear only after confirmation. A failed or uncertain save removes the preview and retains the original Retry/Discard recovery; no rollback write can overwrite unrelated edits. A reload or account/planner switch does not carry an unconfirmed visual preview into the new view. Cross-section moves, archive, and Undo retain confirmed-save behavior.
# Additional task tools (Stage 4)

Task menus include Duplicate and scheduled date, deadline, priority, duration, reminder and AI-lock tools for one or up to 50 selected ordinary tasks. Each field tool changes only that field (plus the existing duration-derived times), validates the whole set and uses one recoverable receipt with guarded field Undo. Mixed values are identified in the dialog. Recurring parents direct users to their existing Details/Schedule editors.

Duplicate creates unscheduled ordinary copies with fresh task/checklist IDs and unchecked progress, preserving supported notes/priority/deadline/duration/reminder/colour metadata. It excludes recurring rules, occurrence exceptions and operation history. IDs remain stable through Retry. Like quick-add, creation has no Undo; archive unwanted copies.

Dragging a selected task's grip moves the visible selected set in traversal order with a count indicator, one batch Move and one Undo. Drop above/below an unselected task or into section space. Dragging an unselected task stays a single-task action. Escape, invalid/outside drops, scope changes and sorted views cancel group dragging.

Right-click section space for Add task, Select tasks in section or Collapse section; keyboard context-menu entry also works from section controls. One shared menu handles task/section contexts and preserves native editing/page menus. Add opens the existing quick-add form; it does not create a blank task.

# Atomic bulk actions (Stage 3)

Select up to 50 tasks, then choose Complete, Mark incomplete, Move to section or Archive (under More). Completion actions explicitly set every selected task to the requested state; they never flip each task individually. Recurring parent series cannot be bulk-completed: use their occurrences in Schedule.

Each batch validates all selected task identities, locations and affected values before one transaction. A conflict rejects the whole batch. Move appends selected tasks in visible traversal order, retaining unselected/hidden task order and all task metadata. Archive confirms the count and retains the dirty-details guard.

Completion and Move provide display-only previews; rewards and the single ten-second Undo appear only after confirmed persistence. Lost responses keep the original batch receipt for Retry, including after reload. Selection, Copy and Clear remain usable during recovery, while further mutations remain blocked. Undo checks the affected flags/order and preserves unrelated edits. More than 50 selected tasks disables bulk mutations with an explanation.

Title/date editors on tasks in an unconfirmed bulk Move (or its Undo) are temporarily disabled, including during uncertain recovery. They become available after confirmation or explicit Discard. This prevents inline edits from addressing the preview destination before canonical location is confirmed; unrelated tasks remain editable.

# Task selection (Stage 2)

Click task row space to select one task; Ctrl/Cmd-click toggles tasks across visible boards/sections. Shift-click selects the visible range within the anchor section, and Ctrl/Cmd+Shift-click adds that range. Ctrl/Cmd+A selects visible Tasks rows outside editors. Escape clears selection after menus, dialogs and dragging have released it. Title/date/completion controls and drag grips retain their own behavior.

Selected rows have a surface and border highlight. The count and toolbar appear above the task content, clear of save/Undo status. Select task/Deselect task is available in the task menu without modifier keys. Right-clicking a selected task retains the set; an unselected task replaces it. Multi-task menus display the affected count and include Copy titles and Clear selection alongside eligible bulk actions.

Selection is transient and does not write planner data. Refresh/reorder preserves valid IDs, hidden/archived/missing tasks are pruned, and changing account, planner or overview/expanded section clears the selection and range anchor.
