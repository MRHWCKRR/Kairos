# AI native event actions

User authorised extending AI event actions to match the native Schedule editor: dated appointments, weekly, all-day and overnight events, conflict review, shared guarded saves/recovery and Undo. Existing OpenRouter request path/auth/budgets/model configuration stay unchanged. No new provider or secret.

Extend existing create_schedule_event/update_schedule_event/delete_schedule_event args with date, allDay and transparent. date means one-off; day (Sunday=0) means weekly; never accept both. A new event needs a title, explicit date or weekday, and start/end unless allDay:true. Missing/ambiguous times or relative dates require clarification rather than invented duration. Resolve relative dates using the existing profile-local date/time context. Updates target exact ID or an unambiguous full title; no ID fallback. date converts weekly to one-off; day explicitly converts to weekly. Date-only updates retain times. A start-only timed move preserves original duration including midnight/overnight. Explicit end permits resizing; changing all-day to timed requires both boundaries. Imported source-owned/read-only targets always fail.

Approaches considered: add more legacy event mutation cases (keeps two validation paths), create new action names (breaks compatibility and duplicates intent), or adapt existing action names to native-event commands. Choose adapter ai-event-actions.js with native preview/apply guards and existing chat confirmation UI. No natural-language parser, new calendar recurrence system or AI auto-apply.

Every event change requires a native command preview. Approval binds pinned action/target, native command and scheduling baseline. Creation ID is generated once per retained preview. Store event previews in the durable pending chat batch before confirmation, just like planning commands. On retry/reload, reconcile confirmed receipt first; otherwise reuse the exact preview, command and operation identity. Old queued event actions without approval must obtain a fresh review. Account/chat/planner changes cannot apply to the wrong scope. Schedule, target or timezone changes refuse stale approval. Busy overlaps are allowed only after explicit review and never move tasks. Weekly overlap window remains labelled today..+30 with legitimate overnight tails.

Event confirmation shows before/after fields, profile timezone, all-day/next-day/busy/free semantics and escaped task overlaps. Success text distinguishes one-off from weekly and is generated from confirmed result only. Follow-up target memory retains the actual saved event ID. Missing or false execution results cannot claim success.

AI event receipts carry nativeEventUndo. Undo AI change resolves the latest supported AI receipt, uses the native event Undo preview/command and shared session/one-use receipt marker, shows restored event/task overlaps, and refuses later event changes or imported identity reuse. Do not also create a generic plannerUndo for these receipts, which would provide a second inverse path. Other AI actions retain their current Undo behavior. Manual native UI receipts are not labelled AI changes.

Test schema/parser, model mapping/intent binding, transaction approval/retry/timezone and Undo, chat persistence/confirmation/escaping, mixed action order and real Chrome event workflow using isolated persistence. Keep existing task/planning actions and mobile block. Publish reviewed PR, verify full suite/build/browser/CI, hold merge/deploy. No live model or authenticated Firebase verification claim without doing it.
