# Native events in Schedule

Choose + Event in Schedule or Edit event from a native event inspector. Events default to the selected Schedule date. Use Does not repeat for one date, or Every week for an existing weekly commitment. All day covers the whole date/day. A timed end earlier than its start ends the next day; the editor labels this explicitly. Show as busy reserves time; free events remain visible.

Review event lists unfinished task overlaps before Save event. Dated reviews include overnight continuation; weekly reviews check today through 30 days ahead and state that later weeks are not checked. Saving does not move tasks or require appointments to fit task work hours. Schedule/timezone changes invalidate a review. Imported events remain read-only and are managed through Calendars.

Delete event opens a deletion review. Preview Undo shows the prior event and any restored overlaps, then Apply Undo confirms it. Undo uses one owned receipt once, refuses intervening event edits/identity reuse, and preserves unrelated tasks/events. Lost responses retry the original command identity. Account/planner switches clear the visible draft; clearing recovery retains inputs but requires a new review. Dirty drafts request confirmation before closing or reloading.

One-off sleep events produce bedtime reminders only on their stored date; all-day/free events do not. Existing weekly sleep reminders retain their behavior. Event upserts/restores are bounded to 500 native events and 700 KiB planner state; deletion stays available for cleanup. Exceptionally large legacy event metadata may omit Undo rather than block cleanup. No provider writes, billing changes or new dependencies.

Choose Every 2 weeks for fortnightly events. Reference occurrence date must match the weekday and determines which alternating weeks occur. It is not a first-date limit: earlier matching weeks also occur unless First date restricts them. First/last dates remain independent, so changing term dates never flips the alternating pattern. Review shows the repeat interval and reference date. Restore saved individual exceptions before changing weekday, interval or reference date. Opening an off-week date safely opens the series editor.

AI event creation/updates accept intervalWeeks: 1 or 2 and anchorDate: YYYY-MM-DD on entire series only; interval 2 needs a known same-weekday reference occurrence. AI preserves these values on ordinary edits and asks for a missing reference instead of inventing alternating weeks. Shared projection keeps Schedule, Month, Today, task planning, conflicts, bedtime reminders and .ics snapshots consistent. Existing records without interval fields stay weekly; no migration is required. Task recurrence and imported calendars retain their existing behavior.

Event reminders

Timed native events offer 5, 15, 30 or 60 minutes before, Off, and Use default. Default preserves the existing 15-minute sleep/bedtime reminder (subject to the bedtime setting); other event categories have no default reminder. Off disables both custom and automatic bedtime for that event/occurrence. Custom sleep reminders replace bedtime delivery and follow the main notification enable setting. Custom reminders can be used on free timed events; all-day conversion clears custom reminders to Off. Imported calendar events remain read-only.

Series reminders follow weekly/fortnightly cadence and original-date bounds; moved occurrences notify at their destination, skips stay silent, and individual overrides can choose custom, default or Off. Restore occurrence returns to series settings. UI and AI edits require review and retain normal Retry/Undo behavior. AI create/update_schedule_event accept reminderMinutes:5|15|30|60|null|'default'; omission preserves updates. Removing an event reminder never means deleting the event.

Delivery uses existing in-app notifications and durable, planner-scoped receipts. Reminder checks run while Kairos is open, on saves/focus and each minute. Browser popups additionally require browserPush and granted permission. Saving never grants permission or proves delivery. No background service, email/SMS or alarms in calendar exports are added. A delayed check can deliver until the event starts, then stops. The profile timezone controls wall times, with DST gaps suppressed and ambiguous starts using the earlier instant.
